First-alert onboarding

From install to first alert, with one thing to type.

Today a new merchant opens Snoopie to an empty page and an 8-field form. This proposal replaces that with three short steps. The only thing they type is the store they want to watch. Everything else is a sensible default or something Shopify already told us.

What a new install sees

Redrawn from the current admin screens, with example data in place of real stores and emails.

  1. The empty state doesn't explain an alert. One button, plus a Guide link to a page that holds another button. Nothing shows what a good first alert looks like.

  2. Create opens a settings form, not a first step. 8 fields on screen, 7 required, before the merchant has seen any value.

  3. The trigger is a dropdown of long sentences. Price changes, the feature we lead with on the listing, sits among equal options.

  4. The threshold is an abstract percentage. "10" means nothing until you see it as dollars on a real product.

  5. We ask for things we already know. The merchant types their own email, which Shopify gives us, and invents an alert name we could generate.

  6. Silence after Save. The first proof Snoopie works arrives whenever the competitor next changes something. Until then, an app that stays quiet looks like an app that doesn't work.

Goal

Every new install leaves its first session with a saved, verified alert and knows what the first email will look like.

    After the wizard

    Keep guiding until the first real alert lands

    On the Alerts page

    Setup checklist

    • Create first alert, send a test alert, connect Slack or Discord, open Price History.
    • Stays until all four are done or the merchant dismisses it.
    • Merchants who skipped the wizard land here with one button to resume it.
    In the alerts table

    Say what "Active" means

    • Status reads Watching · no changes yet until the first alert fires, then the date of the last change.
    • One line under the table: no email yet means the competitor hasn't changed anything.
    By email

    One nudge, one celebration

    • 24 hours after install with no alert: a short email with a link straight into step 1.
    • First real alert: append one line, "This is your first Snoopie alert", plus a link to Price History.
    Measure

    Events to add and what we judge it on

    Pull today's baseline from these events before launch, then set targets. If install volume is too low for a split test, compare the 30 days before and after launch.

    • onboarding_viewedStep 1 rendered for a shop with zero alerts.
    • competitor_verifiedVerify succeeded. Log source (Shopify / Amazon) and failures with reason.
    • trigger_selectedWhich trigger, and whether the threshold was changed from 10%.
    • first_alert_savedAlert created from onboarding. Log seconds since install.
    • test_alert_sentFrom the success screen or the checklist.
    • onboarding_skippedWhich step they left from.
    • first_alert_deliveredThe first real change notification reached the merchant.
    Install → alert savedShare of installs with a saved alert within 24 hours. Primary metric.
    Install → first alert deliveredWithin 7 days. Shows whether the defaults pick alerts that actually fire.
    14-day retentionStill installed two weeks later, compared against the pre-launch cohort.
    Build scope

    Most of it reuses what exists

    Frontend only
    • 3-step wizard calling the existing create-alert and verify endpoints.
    • Prefill email from the shop record; generate alert name.
    • Trigger cards, threshold presets and dollar example.
    • Checklist card and the "Watching · no changes yet" status.
    Small backend
    • Send-test-alert endpoint using the real email template and sender.
    • Verify returns store name and, if cheap, product and collection counts.
    • Per-shop flags: onboarding done, checklist dismissed.
    • 24-hour nudge email and first-alert line.
    Rollout
    • New installs see the wizard on first open.
    • Existing shops with zero alerts see it on their next open.
    • Shops with alerts see nothing new except the clearer status.
    Open questions

    Decide before we build

    • Q1

      How often does Snoopie check a store?

      The success screen should say when the merchant can expect to hear from us. Right now it can only say "the moment it happens".

    • Q2

      Can verify return the store name and product count?

      Showing "Lumen Goods · 248 products" back is what makes step 1 feel like Snoopie found the right store. Store name alone is enough to ship.

    • Q3

      Price changes as the default, or new products?

      Recommendation: price. It's the listing's lead, and the 10% threshold keeps the volume sane. New products may fire sooner on busy stores; the 7-day delivery metric will tell us.

    • Q4

      The plan includes one alert. What happens when the merchant wants a different competitor later?

      Edit should allow changing the URL so they don't have to delete and recreate. Worth checking before we point people at "change it later".

    • Q5

      Should the test alert use the real sending path?

      Recommendation: yes. It proves deliverability and lets us tell merchants to check spam on day one, not on the day a real alert gets lost.

    • Q6

      Stock alerts stay out of onboarding.

      They're on the listing but not in the current trigger menu. Add a card once the trigger ships.
